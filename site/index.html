Follow one HTTP request from a socket to your servlet

A servlet only fills in a response object. Everything else in an HTTP exchange is text on a TCP connection, read and written by the server around it: by a hand-made ServerSocket loop in the first lessons, and by Tomcat later.

Every request and response on this page is real: recorded from this repository's code.

    One object, many requests
    
    
    Tomcat creates a servlet once and calls it for every request, from many threads at a time. That is why a servlet keeps no
      per-request data in its fields. FirstServlet prints its lifecycle to the Tomcat log:
    
    
    
      
    init()
    Once, on the first request to /first (or at startup with load-on-startup).
    
      
    service()
    For every request. HttpServlet picks doGet, doPost… by the HTTP method, or answers 405.
    
      
    destroy()
    Once, when Tomcat stops or redeploys the application.
    
    
    
    
    Tomcat log while the requests above were recorded (what the servlets printed with System.out)
    
    
    
  
    

    


    
  
    
    
    This is the core of Spring MVC
    
    
    Spring does not replace servlets, it is built on them. A Spring Boot web application is the same picture with one servlet
      that forwards every request to your controllers.
